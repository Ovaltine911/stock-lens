## 2. 部署形态与缓存

使用**单实例常驻 Node.js 20+**，或由平台/反向代理提供HTTPS的单实例Docker。服务端同时提供静态页与API：

- 自动取数缓存15分钟，跨上海自然日失效；singleflight合并并发请求，缓存命中保留同一 `snapshotId` 与源日期，避免重复消费取数额度。
- 筛选快照另存于进程内，默认30分钟、最多100份；`/api/screen` 必须回到持有快照的进程。
- 重启清空服务器快照；本浏览器保存只可作为历史查看，不能冒充当前快照重算。

不直接使用GitHub Pages等纯静态托管，也不直接扩为无共享状态的多副本或短生命周期Serverless。扩容前需共享快照、全局额度与访问控制；会话粘滞不能解决重启丢失。

## 3. 本地启动与安全配置

在项目根目录执行，已有 `.env` 时先确认不要覆盖：

```bash
npm ci
cp config.example .env
npm start
```

打开 `http://127.0.0.1:4173`。V3正常入口为自动真实数据，无需选源/手动加载；未配置数据凭证会明确报错。可通过次级独立演示入口体验合成样本，不自动退demo。

### 仅本机配置入口

```bash
node scripts/setup-model.mjs
# http://127.0.0.1:4174

node scripts/setup-fuyao.mjs
# http://127.0.0.1:4175
```

两个脚本共用安全配置服务器，各自验证供应商：DeepSeek验证模型列表；扶摇验证一个证券的估值接口与业务成功结构。**保存成功不是全部推理/行情/财务能力验收。** 验证会访问外部API，可能消耗额度，不作为离线回归的一部分。

- 仅绑定回环地址，检查Host、Origin和令牌，有并发/尝试限制与覆盖确认；不可通过隧道、反代或公网暴露。
- 配置存于 `.local/model.json` / `.local/fuyao.json`，目录0700、文件0600；状态接口不返回凭证。
- 模型本地配置由开发运行读取，`NODE_ENV=production` 时不自动读取，生产用平台Secret。
- 扶摇本地文件不会自动搜索：运行产品时显式设置 `FUYAO_CONFIG_PATH=.local/fuyao.json`，或配置 `FUYAO_API_KEY`；环境密钥优先。
- 配置后关闭配置进程。不要将密钥粘贴到聊天、命令参数、URL、截图或日志。

本次工作区扶摇已安全保存并由主协调完成全12股本机验证，不需为更新文档重新探测；该文件不复制到云端或提交包。

## 4. 生产环境变量

真实值仅放平台Secret/Environment管理，不放仓库、前端变量、构建参数或URL。

| 变量 | 用途 |
| --- | --- |
| `NODE_ENV` | `production`，禁止自动加载本机模型配置 |
| `HOST` / `PORT` | 通常 `0.0.0.0` 和平台分配端口 |
| `APP_ORIGIN` | 产品完整HTTPS origin，不含路径，用于跨站检查 |
| `LLM_API_KEY` / `LLM_MODEL` / `LLM_BASE_URL` | 实际获授权的OpenAI-compatible模型配置；DeepSeek按官方地址配置 |
| `FUYAO_API_KEY` | V3自动数据主源的服务端Secret；**云端已安全配置，真实主流程已验证** |
| `FUYAO_CONFIG_PATH` | 可选显式受保护文件路径，本机使用；生产优先Secret，不上传本机文件 |
| `IFIND_API_KEY` / `IFIND_CONFIG_PATH` | 可选PE/PB/ROE有限备用，不与扶摇混用凭证；生产优先Secret |
| `PUBLIC_DATA_ENABLED` | 仅值为 `true` 启用历史公开适配；不是V3正常入口的用户选项 |
| `REVIEW_USER` | 评审登录名，默认reviewer |
| `REVIEW_PASSWORD` | 至少16字符；生产配置模型/金融凭证或金融配置路径时强制要求 |

生产缺失/过短评审口令会拒绝业务访问。健康检查 `GET /api/health` 例外，只显示配置状态，不泄露行情与秘密；`configured` / `autoAvailable` **不等于认证、额度、联网或取数成功**。使用HTTPS，评审账号仅通过私有附件交付。访问保护不能代替金融数据展示授权。

自动模式以扶摇为主，只在缺少PE/PB/ROE且iFinD已配置时有限补充，不做无差别双源拉取。iFinD仍是固定日期适配，不可把其日期改成当前日期以宣称实时。详见 [数据说明](DATA_SOURCES.md) 与 [AUTO_DATA.md](AUTO_DATA.md)。

## 5. 后续发布的复用步骤

本次V3已发布；以下为以后更新时重复执行的操作规范，不表示当前尚未上线。

1. 完成变更并冻结集成版本；运行 `npm test`、`npm run test:e2e`、`npm run check:design`，保留退出码及版本信息。
2. 审查明确单提交、模糊单确认、无选源/加载、证据、对比、历史、错误恢复和窄屏深色；未验收不部署替换旧版。
3. 逐文件审查敏感内容、Git差异、忽略规则、镜像上下文和提交包；记录最终commit并推送既有公开仓库。
4. 在平台秘密变量配置扶摇，核对既有模型/iFinD和评审保护；设置单实例、`APP_ORIGIN`、HTTPS与健康检查。
5. 显式重新构建部署。不要仅凭GitHub已推送判断运行代码已更新；仅文档变更通常无需重新部署运行服务。
6. 从外部浏览器与受控API完成第7节验收，确认后更新运行commit、部署标识、截图与文档。
7. 失败则保留真实错误和未完成状态，必要时保留/回退已验证V2，不用合成结果冒充新版本成功。

### Node / Docker

Node安装命令 `npm ci --omit=dev`，启动 `npm start`，健康路径 `/api/health`。外部超时应容纳合法模型和数据请求，不能只看健康检查成功。

```bash
docker build -t stock-lens .
docker run --rm -p 4173:4173 --env-file .env stock-lens
```

Docker示例用于本机；生产由平台注入Secrets，勿分发 `.env`。Dockerfile使用Node22 Alpine、非root与白名单复制。示例命令不构成本轮V3镜像已构建/部署的证据。

当前速率/并发保护是原型级，反代用户可能共享IP桶，不是账号级计费系统。需要关注平台余额和供应商预算，不承诺永久免费，不自动升级付费。日志仅记录必要状态/时延/安全错误码，不记录认证头、用户全文或私有响应。

## 8. 60–180秒演示建议

优先从独立演示入口使用合成数据，明确模型是否真实；如展示授权真实数据，先核对展示范围。

- **0–30秒**：说明12家观察样本、非全市场、非买卖建议；输入明确条件并一次“开始筛选”，不用选源/加载。
- **30–60秒**：查看一条证据，说清实际值、阈值、日期与期间；解释未通过与数据不足不同。
- **60–100秒**：输入模糊示例，说明年度、PE25与波动率30是建议，单按钮确认，非客观投资标准。
- **100–140秒**：改阈值并“更新结果”，展示同快照差异，不称为回测；查看候选横向比较。
- **140–180秒**：保存/恢复历史，说明只读；展示冲突或错误恢复，解释模型/数据/引擎分工。

候选人需亲自走查理解，不把AI生成脚本当作本人已演示。现场调用失败应保留真实错误；可显式转演示，但不能把演示说成真实请求成功。
