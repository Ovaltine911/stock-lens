# 产品说明：从调试工作台到一句话筛选

## 1. 产品定位与改版反思

**选股有据**把研究意图转成可检查的条件，在有来源的数据快照上筛选，并解释每一条结论。它是同花顺 AI 产品经理笔试原型，非同花顺官方产品；“通过”只表示满足条件，不表示值得买入。

V2 已有解析、证据、比较和保存，但将“选择供应商 → 加载数据 → 解析 → 勾选说明 → 确认执行”变成了用户必须理解的流程。用户明确指出操作繁琐，要求系统自动取数，并委派前端审美 Worker 参考同花顺风格改版。

**产品经理反思：技术模块齐全不等于任务顺畅。** 供应商、缓存和请求编排应是系统责任；透明应体现在结果证据和“数据与口径”入口，而不是让用户先做供应商选择题。确认也应只服务于真实的语义歧义，不应成为所有请求的仪式。

| 旧版负担 | V3 决策 | 不能牺牲的边界 |
| --- | --- | --- |
| 用户先选源、手动加载 | 正常入口只保留自然语言框和“开始筛选”，后台自动取数 | 始终显示 12 家样本、非全市场和真实数据日期 |
| 明确条件也重复确认 | `needsConfirmation=false` 时单次提交自动执行 | 精确保留指标、比较符和阈值，条件仍可编辑 |
| 模糊说明逐项勾选 | 3 条简明解释 + 一个“按这些条件筛选”按钮 | 年度、估值阈值和波动窗口的假设必须看得见 |
| 为了少点击隐藏来源 | 来源信息降为次级入口，证据保持完整 | 不静默退 demo，不混淆供应商日期或财务口径 |
| 卡片堆叠像开发工具 | 金融红强调、白灰底、紧凑横向信息与数字表格 | 不伪造指数条，不冒充官方，不混淆通过/失败与涨跌颜色 |

这些是**设计上的步骤减少**，不是用户任务耗时、满意度或收益的实测提升。尚未进行访谈或可用性实验。

## 2. 目标用户是假设，不是研究结论

假设用户是有基础研究意图、但不熟悉筛选语法的个人投资者：能说出“经营改善、估值合理、走势稳定”，愿意核对少量候选，不要求原型承担全市场研究或交易执行。

主要待验证风险：把建议阈值当行业标准；把未知当不达标；把流畅文字当证据；改条件时把行情变化误当条件效果。价值假设是：**更少的操作负担，加上可检查的条件和证据，能帮助用户理解系统实际做了什么**。目前没有需求规模、转化率或效率提升数据。

## 3. V3 核心流程与状态契约

以下是当前改版的交互目标与验收标准；后端已有本机验证，前端仍待最终浏览器验收，不能据此声称全部已上线。

### 明确条件：一次提交

输入 `市盈率大于0且市盈率不高于25且净资产收益率大于10%` → “开始筛选” → 模型/规则生成可编辑条件 → 后台自动快照 → 确定性筛选。

当意图没有新增假设、不支持项或阻断，`needsConfirmation=false`，无需再点击确认。后端 `/api/screen` 的 `confirmed:true` 是结构化执行前置字段，不是要求用户每次额外点击，更不是不可篡改的签署记录。

### 模糊表达：只确认假设一次

输入 `经营改善、估值合理、走势相对稳定` → 5 条草稿 + 3 条解释 → 用户检查或编辑 → “按这些条件筛选” → 自动取数和筛选。没有复选框，不提前执行未经确认的建议。

| 模糊表达 | 可编辑建议 | 必须解释 |
| --- | --- | --- |
| 经营改善 | 年度营收同比 >0%，年度归母净利润同比 >0% | 最近两个已披露完整年度，非最近季度，不等于经营拐点或利润质量改善 |
| 估值合理 | 0<PE(TTM)≤25 | 25 是产品起始阈值，不是普适合理价值；负 PE 不等于低估 |
| 走势相对稳定 | 20 日年化波动率 ≤30% | “相对”不是自动与指数/行业比较；短期低波动不代表未来低风险 |

明确的 `PE<20` 不得被偷偷加上 `PE>0`。明确年度同比无需再确认年度；明确季度要求不能换成年度来制造可用结果。当前累计同比字段仍缺失，不能表达的具体季度/期间应明确指出。

### 编辑、错误与历史

- 条件冲突、不支持要求不得静默丢弃。可重新表述，或显式“改为手动条件”并清空后重新定义；合规阻断不能继续执行原请求。
- 新输入使未提交草稿失效，不自动发送；晚到响应不能覆盖新输入。
- 改已执行条件时，旧结果标为历史/待更新，不能当新条件结果保存或导出；点“更新结果”只在原 `snapshotId` 上重算并展示集合差异。
- 新增未加载字段不应悄悄换快照取数；不可用字段保留未知。快照失效须重新查询，不用历史记录冒充当前快照。
- 结果分通过、未通过、数据不足；保留逐字段实际值、阈值、来源、日期、期间、单位、原始字段和原因；支持 2–3 个候选横向对比。
- 本浏览器保存与恢复须有 V3 schema 校验；恢复结果明确为只读历史。不是云端账号或策略库。
- 模型、数据、筛选错误分别提示，仅真实失败才显示错误横幅；成功、首次加载和重试恢复不能残留假错误。

## 4. 模型、数据与引擎各自负责什么

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `lib/llm.mjs` | 受目录约束的 JSON 草稿、假设与不支持项，提示词 `intent-v2.0` | 拉行情、补值、决定是否通过、推荐买卖 |
| `lib/intent.mjs` | 无模型配置时的有限规则解析，明确显示模式 | 冒充通用大模型；已配置模型失败时伪装成功 |
| `lib/auto-data.mjs` | 主源扶摇、有限 iFinD 补充，日期/单位/字段审计 | 失败退演示、猜同比口径、把抓取时间当数据日期 |
| `lib/engine.mjs` | 条件校验、冲突、AND 三值逻辑、同快照差异 | 放宽阈值、把缺失置零、用解释替代计算 |
| 前端 | 按 `needsConfirmation` 编排请求、展示进度与证据、维护状态 | 自己猜是否有歧义，隐藏未支持要求，伪造数据 |

模型 JSON 合法不等于语义正确。条件数来自已校验结构；`unsupported` 必须逐字锚定原文，可阻止部分凭空添加的限制，但不证明没有漏条件、误解或误拒。

## 5. 数据范围、口径与真实进展

目录现有 **10 个指标，最多 16 条 AND 条件**，比较符为 `>`、`≥`、`<`、`≤`、`=`。目录可表达不等于真实数据全部可用。真实观察池固定 12 家，演示则为 12 个虚构名称和代码，均非全市场。

V3 本机全量自动快照：正常主源 19 请求、HTTP 200、1570ms；PE/PB/ROE/20日波动率/20日价格变化/年度营收同比各 12 `ok`，年度归母利润同比 11 `ok`、1 `missing`，原累计营收/利润同比及市值各 12 `missing`。年度增长 + PE + 波动率五条件为 5 通过、7 未通过。见 [V3 验证记录](V3_VALIDATION.md)，不能外推全市场、长期稳定性或云端延迟。

关键口径：

- **日期不是统一写死的某一天**：auto 由交易日历确认最近交易日；估值采用上游元数据时点并单独说明，可能与最近交易日不同；财务保留报告期和披露/修订元信息。`fetchedAt` 仅为读取时点。
- **年度同比**：同供应商最近两个相邻已披露完整年度（例如 2025/2024，随响应更新），按 `(当年原值/基年原值−1)×100` 计算。保留两年 raw、币种、期间、分子和分母；基年≤0时缺失，不能把扭亏包装成常规增速。年度不是累计季度的替代品。
- **ROE**：仅报告期加权平均字段；按官方百分数值直接解释，不因数字小就乘100，不混用摊薄或年化指标。
- **20 日价格指标**：最近 21 个前复权收盘价须与日历对齐。对数收益率样本标准差（分母19）×√252×100 为年化百分数值；首尾价格比减1再×100 为价格变化，不是含费用和分红再投资的策略收益。
- **有限备用**：只有扶摇 PE/PB/ROE 不可用且 iFinD 已配置时补充；正常主源齐全不请求 iFinD。其固定估值日 2026-11-06、ROE报告期 2026-09-30 仍须原样披露，不能伪装“自动最新”。

自动取数缓存 15 分钟、跨上海自然日失效，singleflight 合并并发请求，命中保留 `snapshotId` 与数据日期；筛选存储默认 30 分钟、最多100份，重启清空。缓存只减少重复取数，不提高数据新鲜度，也不把条件差异变成回测。详细合同见 [数据说明](DATA_SOURCES.md) 和 [自动适配说明](AUTO_DATA.md)。

## 6. 证据与三值结论

仅当数值有限、`status=ok`、来源和原始字段存在、日期有效且单位/期间与目录匹配时才参与比较。

- **通过**：全部条件证据可用且满足。
- **未通过**：至少一个条件明确不满足；其他未知证据仍保留。
- **数据不足（unknown）**：没有明确失败，但至少一个条件无法确认。未知不是“公司不好”，也不能通过。

本机五条件结果 `unknown=0` 仅指股票整体结论，不表示所有单项完整。来源链接不等于已核验公告原文；披露/修订日期不等于已证明首次可获得时间，当前数据不能支持无前视偏差回测。

## 7. 不做什么

不做全市场、任意股票池、OR/嵌套逻辑、行业成分/ST排除、新闻/分红、任意财务期间、回测收益排名、自动交易、仓位建议或定时监控。选择有限范围是为了把证据做实，不靠扩大股票数掩盖数据质量。

查询授权不等于公开再分发权。生产使用模型/金融凭证须设置评审访问保护；公开仓库不包含密钥、私有原始响应和受限数据截图。未收集用户持仓或新增外部追踪。

## 8. 验证计划与下一步

目前真实模型明确条件 3 条、`needsConfirmation=false`、2567ms；模糊条件 5 条、3 条解释、`needsConfirmation=true`、8486ms。都是本机单次案例，**不是准确率或 P95**。单元/接口121通过；V3浏览器8条待验收，见 [测试说明](TESTING.md)。

后续用户测试应在同意后招募5–8位假设画像参与者，使用合成数据，不收集账户或持仓，交叉安排新旧流程；观察：

1. 无协助完成明确筛选与模糊确认的比例、任务耗时和额外提示次数。
2. 能否指出系统建议、修改阈值，并解释年度不是季度。
3. 能否区分未通过和未知，找到来源、日期与原始字段。
4. 能否理解同快照差异与历史恢复，不误认为收益验证。
5. 冲突、不支持、服务失败后的恢复路径是否清楚。

语义准确性应另建标注集，覆盖明确/模糊/冲突/不支持/合规/注入，记录分母和版本；延迟应记录足量成功与失败分布，不能用两次调用推导 P95。未知误通过、条件静默丢弃和密钥泄露为发布阻断项。

**当前优先级**：完成 V3 前端与浏览器验收 → 冻结集成版本 → 云端配置扶摇、重新发布并做公网验证 → 更新截图、文档和打包。公网仍为 V2 `a8462ee`；[V2 公网记录（历史）](PRODUCTION_VALIDATION.md) 仅证明旧版。无需重新把已完成的 GitHub 公开/授权写成待办；仍待候选人本人演示走查与展示权益复核。
