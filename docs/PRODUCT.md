# 产品说明：先确认条件，再讨论结果

## 1. 产品定位与待验证假设

**选股有据**是自然语言选股与策略解释原型：把研究意图转成可编辑的条件草稿，在有来源的数据快照上执行，并让用户核对每条结论。不做涨跌预测，也不把“筛选通过”表达成“值得买入”。

### 假设用户画像，不是访谈结论

- 有基础投资研究需求的个人投资者，能说出“经营改善、估值合理、走势稳定”，但未必知道应该使用什么指标、期间和阈值。
- 愿意核对少量候选，不需要本原型承担全市场研究、专业量化研究或交易执行。
- 可能把系统建议的阈值当作行业标准，把缺失值理解成不达标，或把一段流畅解释误当成证据。

**尚未开展真实用户访谈或可用性测试。** 上述画像与风险是产品假设，不能据此声称存在经过验证的需求规模、效率提升或满意度。

| 问题假设 | 价值假设 | 可观察的验证方式 |
| --- | --- | --- |
| 用户的模糊表达与实际指标之间存在理解差异 | 先展示草稿及口径，比直接给股票名单更容易发现误解 | 能否指出建议阈值、修改条件并解释修改含义 |
| 用户难以判断筛选结论是否可信 | 同时展示实际值、来源、期间和未知原因，可降低盲目信任 | 能否正确区分“不满足”与“没有足够证据” |
| 改条件后，行情变化与条件变化容易混在一起 | 在同一快照上比较，能说明新增/移除候选由什么条件变化造成 | 能否说清差异不是收益回测，也不是行情变化 |

本作品优先证明的是**研究过程可检查**，不是选股收益更高。

## 2. 核心流程与职责边界

1. **选择并加载数据来源**：明确区分虚构演示、公开数据与需授权的数据服务。
2. **输入研究意图**：规则或模型生成草稿，标出需澄清和不能表达的要求。
3. **用户检查与确认**：逐条核对指标、比较符、数字和期间；模糊草稿需确认解释。存在不支持项时不直接执行部分意图，需重新表述或明确转为手动定义。
4. **确定性筛选**：只在已加载快照上执行已确认条件，不由模型计算通过与否。
5. **查看证据、比较和保存**：检查通过/不通过/未知，修改后重新确认；同快照查看候选集合差异；本地保存仅供当前浏览器恢复查看。

| 参与者或模块 | 负责 | 不负责 |
| --- | --- | --- |
| 模型适配 `lib/llm.mjs` | 理解措辞，生成受指标目录约束的 JSON 草稿，提出澄清 | 拉行情、填补缺失、计算筛选结果、推荐股票或执行交易 |
| 规则解析 `lib/intent.mjs` | 未配置模型时提供有限语法与显式标识 | 冒充大模型、声称理解任意表达 |
| 用户 | 接受或修改建议阈值，确认实际研究条件 | 不能因点击确认而消除数据授权或投资风险 |
| 引擎 `lib/engine.mjs` | 校验、冲突检查、数值比较、三值汇总、同快照差异 | 自动放宽阈值、把缺失置零、用文字判断代替数值比较 |
| 数据适配 `lib/data.mjs` | 取数、字段映射、日期/单位/来源核验与异常标记 | 把失败悄悄替换成演示数据、把抓取时间冒充指标时间 |
| 界面 `public/app.js` | 呈现证据与确认状态；编辑或切源后使旧结果失效 | 把历史记录显示成当前可执行服务器快照 |

模型的 JSON 合法不等于语义正确。`intent-v1.1` 将条件数量从结构计算，并校验 `unsupported` 必须逐字包含于用户原文；这能阻止部分无依据限制，但**不能证明模型没有漏条件、误解期间或误拒请求**。

## 3. 有意收窄的范围

### 本期实现

- 固定 12 家观察样本；演示模式为 12 个虚构名称和代码，真实观察池见 `lib/data.mjs` 的 `RESEARCH_POOL`。
- 8 个目录指标，最多 16 条条件，只支持 AND；比较符为 `>`、`≥`、`<`、`≤`、`=`。
- 条件编辑、显式确认、冲突提示、三值结果与字段级证据。
- 同快照修改前后差异、候选横向比较、本地保存/历史查看、当前结果 JSON 导出。
- 桌面和窄屏使用；主链路有单元、接口和浏览器测试。

### 本期不做及原因

| 不做 | 取舍理由 |
| --- | --- |
| 全市场与任意股票池 | 先把有限样本的字段与证据链做实，避免把覆盖规模掩盖成数据质量 |
| OR、嵌套布尔、行业成分、ST 剔除 | 需要更完整的表达模型与数据能力；不能仅靠提示词宣称支持 |
| 新闻、分红、任意财务期间 | 当前目录无法表达或未完成可核验取数，必须显式说明 |
| 回测、收益排名、自动交易、仓位建议 | 数据可获得时点、复权、费用与交易约束都未完备，不能以筛选差异冒充策略效果 |
| 用户账号、云端策略库、后台定时监控 | 先完成单人可演示闭环，当前浏览器存储不等于多用户产品 |

截至 2026-11-08，iFinD 已接入正式产品网页 API：12 股完整快照的 6 次工具请求成功，HTTP 200、单次 25757ms；随后 PE/ROE 条件筛选 HTTP 200。PE TTM、PB MRQ、报告期加权 ROE 各 12 项 `ok`，其余 5 类指标各 12 项 `missing`。这不是仅工具发现或两股探测，也不是公网部署验收；详见 [真实验证](LIVE_VALIDATION.md) 与 [字段核验](IFIND_DATA.md)。

## 4. 把模糊表达操作化，不把建议当事实

指标目录为 `lib/catalog.mjs`；下表中的阈值是可调整的产品起始值，不是投资标准。

| 表达或指标 | 本原型采用的定义 | 局限及确认点 |
| --- | --- | --- |
| “经营改善” | 建议营收同比 `>0%` 且利润同比 `>0%`，目标口径为报告期累计同比 | 累计与单季不得混用；iFinD 返回的营收/利润同比尚未确证累计口径，保持 `missing`，不能冒充已支持；即使有数据也不证明现金流、利润质量、持续性或未来改善 |
| “估值合理” | 建议 `0<PE(TTM)≤25` | 25 不是普适合理价值；跨行业不可直接比较；负 PE 不代表低估 |
| 明确“市盈率小于20” | 保留 `PE(TTM)<20` | 不擅自增加 `PE>0`；因此负 PE 可能满足字面条件，需用户检查经济含义 |
| “走势相对稳定” | 建议 20 日年化波动率 `≤30%` | “相对”在此需澄清，不自动等于与指数/行业比较；短窗口低波动不等于未来低风险 |
| PB(MRQ) | 最近报告期市净率，单位倍 | 必须核验 MRQ 与估值时点，不能把泛化 PB 字段直接贴成 MRQ |
| ROE | 报告期加权平均净资产收益率，单位 % | 不混用摊薄、年化或其他报告期；默认 10 只是编辑起点 |
| 20 日收益率 | 最近 21 个有效前复权收盘价首尾变化百分比 | 是价格变化，不是含费用、税费、分红再投资的策略回报 |
| 总市值 | 总市值，单位亿元 | 不能与流通市值混用；缺少可核验时间不能当作当日有效值 |

计算口径：设最近 21 个有效收盘价为 `P0…P20`，`ri=ln(Pi/P(i−1))`。20 日年化波动率为 `std_sample(r1…r20)×√252×100%`，样本标准差分母为 `20−1`；20 日价格变化为 `(P20/P0−1)×100%`。年化中的 252 为约定交易日数量，不是对未来风险的预测。

### 当前真实数据能支持什么

- 公开东方财富探测中，可靠采用的是前复权日线派生的 20 日价格变化与年化波动率。PE 无法核验为 TTM，不采用；PB/市值虽有数值，但实测时间字段 `f124=0`，不据此判定有效；公开财务指标缺失。
- iFinD 完整 12 股产品 API 已核验 PE(TTM)、PB(MRQ) 与报告期加权 ROE。估值交易日固定为 **2026-11-06**，财务报告期固定为 **2026-09-30**；后者不是公告日或可获得日，不声称在报告期末当时可得。它不是实时数据；营收/利润同比未确证累计口径，另外三项未接入指标均保持 `missing`。
- 因此“经营改善”等完整模糊示例目前适合先用**明确标识的合成数据**演示流程，不应包装成已完成真实财务研究。

## 5. 解释、失败状态与合规

证据的有限数值、`source`、`field`、有效 `asOf`、与目录一致的 `period`/`unit`，以及 `status=ok` 都满足后才参与比较。字段名可为来源专有名称；有来源链接不等于已核验公告原文。引擎不独立证明上游真实性，适配器仍承担口径与时效责任。

- **通过**：每条条件均有可用证据且满足。
- **不通过**：至少一条有可用证据且明确不满足，即使另有未知项；所有单项状态仍保留。
- **未知**：没有明确不满足项，但至少一项缺失、过期、错误或元数据不完整。未知不是“公司不好”，也不能入选。

| 失败或风险 | 当前产品行为 | 仍有的限制 |
| --- | --- | --- |
| 条件矛盾 | 引擎返回冲突，不自行改条件 | 冲突是数值交集检查，不是经济合理性审查 |
| 模型超时/错误/无依据限制 | 明确报错，不静默退为规则成功；可重试或手动定义 | 仍需更广泛语义评测；规则式合规保护可能误伤含否定的表达 |
| 数据失败/缺失 | 字段 unknown 或整次失败，不偷换来源 | 网络、额度、权限、接口结构均可能变化 |
| 快照失效 | 返回失效提示，需重新加载 | 缓存最多 100 份、有效期 30 分钟、进程重启清空 |
| 编辑条件、输入或数据来源 | 旧结果失效，重新确认/加载 | 需要继续补充高并发及晚到响应的针对性测试 |
| 直接买卖或收益承诺请求 | 拒绝并引导为研究条件 | 原型合规提示不等于完整金融服务合规体系 |
| 本地保存与导出 | 历史标识、导出当前结果 | 不能因可导出而推定收费数据可公开再分发 |

日线时效保护目前使用 7 个自然日，长假可能误伤，下一步应采用交易日历。服务器确认字段是执行前置检查，**不是不可篡改的用户签署/审计记录**。公开部署前还需身份、额度与数据授权治理。

## 6. 验证指标：下面是目标，不是实测成绩

先构建标注集，再记录分母与版本，不以少量 HTTP 200 推导“准确率”。建议初期语义集至少 60 条，均衡覆盖明确条件、模糊表达、不支持要求、矛盾、合规及注入/异常表达；由两位评审独立标注并裁决分歧。

| 指标 | 计算方法 | 初期验收目标（待验证） |
| --- | --- | --- |
| 明确条件完整保真率 | 指标、比较符、数值、期间全部与标注一致且无增删的明确意图数 / 明确意图总数 | ≥95%；不自动放宽阈值为硬要求 |
| 不支持要求召回率 | 正确呈现的真实不支持要求数 / 标注的不支持要求总数 | ≥95% |
| 无依据限制率 | 含用户未提要求却列为不支持的输出数 / 总输出数 | 目标为 0；原文包含校验不能替代语义判定 |
| 证据解释正确率 | 能正确说明来源、期间以及通过/失败/未知原因的用户任务数 / 完成核对任务数 | ≥80% |
| 无协助闭环完成率 | 无主持人提示完成“草稿→确认→证据→修改比较”的参与者数 / 参与者总数 | ≥80% |
| 未知误通过数 | 缺失或不合格证据被判为通过的测试案例数 | 0，作为发布阻断项 |
| 解析耗时 | 请求发起至可编辑草稿可见的耗时分布，分开记录成功与失败 | 暂定成功请求 P95≤15秒，需足量真实调用验证 |

成本另记“本轮可核对账单消耗 / 成功解析请求数”，待获得平台用量后再计算，不预填价格。DeepSeek v1.1 三条真实输入均 HTTP 200，单次耗时依次为 10070/3361/3575ms；这不是 P95 或总体准确率。最新自动化回归为 75 项单元/接口与 5 项 E2E 通过，使用构造或注入数据，与 live 验证及用户体验指标分开记录，见 [TESTING.md](TESTING.md)。

### 尚未实施的用户测试设计

招募 5–8 位符合假设画像的参与者，征得同意，不收集资产、账户或真实持仓。每人 20–30 分钟，使用合成数据：

1. 将明确条件转成草稿，说明阈值是否被保留。
2. 处理模糊表达，指出哪些是系统建议，修改一项阈值。
3. 从不通过和未知中各找一例，解释为什么不能混同。
4. 修改条件，说明新增/移除候选与同快照的关系。
5. 遇到冲突或不支持要求，尝试自主恢复。

记录任务完成、耗时、提示次数、错误理解原话；仅在同意后录屏。可对照纯表单筛选，交叉安排使用顺序，避免全部先用同一版本。小样本用于发现问题，不据此推出统计显著提升或总体满意度。

## 7. 24 小时交付分配原则

以下是时间预算建议，不是实际工时记录；剩余窗口变化后按风险重排。

| 预算 | 重点 | 停止条件 |
| --- | --- | --- |
| 3小时 | 题目拆解、画像假设、指标与证据合约 | 能说清用户、边界与不可伪造的数据要求 |
| 7小时 | 确定性主链路与基础交互 | 合成数据闭环可复核，错误路径不伪成功 |
| 4小时 | 模型与授权数据最小验证 | 有真实调用证据；不因接口可连就扩大数据承诺 |
| 5小时 | 集成回归、用户走查、部署 | 优先消除错误结论、密钥暴露和无法访问等阻断项 |
| 3小时 | 说明文档、截图/演示和提交 | 链接真实可访问、状态与代码一致 |
| 2小时 | 缓冲 | 不再加入新范围，以回归和提交为主 |

当前下一优先级是候选人本人走查、GitHub/平台工具授权、源码推送与公网部署，而不是扩大指标数量。候选人已有 GitHub 身份 `Ovaltine911` 并已登录 Railway，但本工具仍未获授权，尚未 push 或公网部署。若数据权益或部署受阻，应保留可运行合成流程并明确未完成项，不能将占位链接或模拟结果当作完成证明。未做用户访谈，也无增长、效率或收益提升验证。
